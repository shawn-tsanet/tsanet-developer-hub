Build against the API

Everything a member integration touches, in six families — plus the one header that changes how failures reach you.

Java client →
Auth

Login & identity

OAuth 2.0 client credentials is the current server-to-server path; POST /v1/login for a ~60 minute JWT is the legacy one. GET /v1/me gives company context.

Partners

Discovery & forms

Search partners, then always fetch the process form fresh before submission — vendors change them, and documentId comes with it.

Cases

Collaboration requests

Create, list with updatedAfter, approve, reject, request and send information, close. Save the token — it keys every later call.

Content

Notes & attachments

Bi-directional case notes with visibility control, and HTTPS push file transfer once both sides have configured endpoints.

Webhooks

Event delivery

Subscribe a callback with its own auth. Payloads are thin — the event names a token and the fetch is what establishes truth.

Errors

Two response modes

By default most rejections return HTTP 500. Send Accept: application/json, application/problem+json to get documented status codes and RFC 7807 bodies.
